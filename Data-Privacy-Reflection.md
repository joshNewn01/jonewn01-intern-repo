### What are the best practices for handling confidential data?

 - Classify and Inventory the Data:
    - Identify the sensitive data types
    - Giving the data an associated "risk level"
    - Mapping where the data resides across systems, cloud apps, and endpoints
- Enforce Role-Based Access Controls
    - Grant only essential access
    - Review permissions regularly
    - Deactivate dormant or inactive accounts
- Encrypt Data in Transit and Rest
    - use a block cipher algorithm like AES-256 to encrypt the data
    - use a higher level cryptographic protocol like TLS 1.3 for communicating/transmitting the data
    - use a full disk encryption for devices
    - utilize Hardware Security Modules for key management
- Define and Enforce Retention Policies
    - DO NOT hold data longer than needed
    - use retention schedules and automated deletion tools
    - audit backups regularly
- Third-party/Cloud Risk
    - Best practices for managing third-party risks include adding data security clauses in vendor contracts and requiring evidence of encryption, access controls, and other cyber hygiene metrics.
- Layered Defenses
    - Data Loss Prevention (DLP)
        - Monitoring file transfers, email, USB usage
        - Blocking risky actions in real time
        - Integrating with identity providers to enforce policy
    - Multi-factor Authentication (MFA)
        - requires second layer of assurance for data access
    - Endpoint Detection and Response (EDR)
        - EDR monitors endpoints for malicious activity
    - Network Segmentation
        - Reduces lateral movement
        - Isolates systems that handle HR, finance, or legal data from general-use networks using VLANs and firewalls
- Continuous Monitoring
    - Continuous monitoring and early detection shortens attacker dwell time and limits damage.
    - Key strategies:
        - crawl dark web forums and ransomware sites for leaked credentials
        - track unusual access patterns or data transfers
        - flag unusual API calls or outbound connections
- Industry Framework Alignment
    - Adopting well-known security frameworks can help the security team ensure the regulatory and industry expectations are met.
    Examples:
        - NIST 800-53/ NIST Cybersecurity Framework: US Gov't and critical infrastructure
        - ISO/IEC 27001: International Security Standard
        - HIPAA Security Rule: US healthcare sector
        - PCI DSS 4.0: Payment processors and financial entities
        - GBLA Safeguards Rule: Financial Services and lending institutions

### How should you respond to a suspected data breach or accidental disclosure of confidential information?

According to the Office of the Australian Information Comissioner, there are four key steps to responding to this event:

Source:
https://www.oaic.gov.au/privacy/notifiable-data-breaches/preventing-preparing-for-and-responding-to-data-breaches/data-breach-preparation-and-response/part-3-responding-to-data-breaches-four-key-steps

Step 1 : Contain
    - Take immediate action to stop/limit the breach

Step 2: Assess
    - Assess the damage
        - Check logs to see where it occurred
        - Evaluate the scope of the breach
        - Identify who (employee and customer) may have been affected

Step 3: Notify
    - Inform both customers and the OAIC Commissioner, if needed
    - If breach is an 'eligible data breach' under the NDB scheme, then it may be mandatory to notify

Step 4: Review
    - Reassess the incident
    - Identify what actions should be taken to ensure future breaches do not occur

## Reflection

### What steps can you take to ensure you handle data securely in your daily tasks?

 - Utilize multi-factor authentication
 - Utilize complex passphrases for accounts
 - Store passwords in a password manager
 - Lock your device whenever you step away
 - Encrypt any files deemed sensitive
 - Never use public access WiFi without a VPN
 - Always backup important data
 - Ensure devices are up-to-date with their security and OS

### How should you store, share, and dispose of sensitive information safely?

 - Enable full-disk encryption
 - Restrict access to files via MFA or Role Based Access Control (RBAC)
 - Transfer files via encrypted links or password-protected archives/files
 - Permanently destroy records using cross-cut shredders or data-earasure software when no longer needed
 - Maintain encrypted backups offline or in secure cloud repositories

 ### What are some common mistakes that lead to data privacy issues, and how can they be avoided?

 - Unclear or generic Privacy policies
    - Publishing copied or vague privacy notices that do not reflect actual data collection and processing methods
    - How to avoid?: Map the data lifecycle - conduct regular data inventories to track what personal data is collected, how/why it is held, and who has access
 - Weak Access Controls and Shared Logins
    - Allowing multiple employees to use the same account or giving broad, unrestricted access to sensitive repositories
    - How to avoid? Implement RBAC, unique user logins, and MFA for all sensitive systems
 - Retaining Unnecessary Data
    - Keeping customer files and data indefinitely instead of regularly auditing and wiping unused data
    - How to avoid? Automate data retention and disposal - establish clear data retention schedules and securely shred physical documents or wipe old digital storage media when data is no longer needed
 - Overlooking Mobile and Cloud Misconfigurations
    - Leaving cloud storage buckets open, failing to encrypt devices securely, or hardcoding security keys
    - How to avoid? Regularly audit third-party vendors - review their data-handling practices, security standards and contracts before sharing the data
 - Social Engineering
    - Staff falling for phishing emails, unverified links, or texting scams
    - How to avoid? Train staff continuously and ensure they are informed of the latest scam tactics
